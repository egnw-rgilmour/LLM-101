Prompts and system instructions

A prompt is simply the input you give the model: your question, instruction, and any context you include. The model responds by predicting a continuation. Better prompts produce better responses, because you're giving the model more to work with.

Many tools also have a system instruction (or "system prompt") set behind the scenes. It establishes the assistant's role, rules, and tone before your messages — for example, "You are a helpful internal IT assistant. Be concise. Never invent ticket numbers." Users don't usually see it, but it shapes every reply.

The context window: the model's working memory

Everything the model considers for a single response — the system instruction, your prompt, and the recent back-and-forth — must fit inside its context window, measured in tokens (Module 4). Think of it as the model's short-term working memory for this one request.

When a conversation grows longer than the context window, the oldest parts fall out of view. That's why a chatbot can seem to "forget" something you said much earlier: it literally no longer sees it. The model has no persistent memory between requests unless the application deliberately stores and re-supplies information.

IT analogy

The context window is like a fixed-size cache. New information pushes old information out once it's full. If something important scrolled off, you have to feed it back in — the model won't recall it on its own.

Temperature: the randomness dial

When the model picks the next token, it's choosing from a ranked list of likely options. Temperature controls how adventurous that choice is. Low temperature makes the model strongly favor the single most likely token, giving focused, repeatable output. High temperature flattens the odds so less-likely tokens get picked more often, giving varied, more "creative" — and less predictable — output.

For factual, structured, or repeatable tasks, lower temperature is usually safer. For brainstorming or varied phrasing, higher temperature helps. Either way, remember the randomness contributes to why answers can differ between runs (Module 10).

Practical prompting tips

  • Give context. State the audience, goal, and any constraints. "Explain to a non-technical manager…" beats "Explain…".
  • Specify the format. Ask for a bulleted list, a table, JSON, or a word limit if you need it.
  • Show an example. One good example of the input/output you want steers the model strongly.
  • Break up big tasks. Ask for an outline first, then expand — rather than everything at once.
  • Tell it what to do if unsure. e.g. "If you don't know, say so rather than guessing." This reduces (not eliminates) made-up answers.
  • Iterate. Treat the first response as a draft and refine your prompt.

Key takeaways

  • A prompt is your input; a system instruction sets the assistant's role and rules.
  • The context window is finite working memory measured in tokens — overflow causes "forgetting."
  • Temperature trades repeatability (low) for variety (high).
  • Clear context, explicit format, and examples reliably improve results.

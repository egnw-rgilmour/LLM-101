Module 02

Machine Learning vs. Deep Learning

⏱ ~12 min read

What you'll learn

  • What "learning from data" really means.
  • The difference between training and inference.
  • What "a model" actually is — and what parameters/weights are.
  • Why GPUs are central to modern AI.

Learning from data instead of rules

Traditional software is rules a person writes: if X then Y. Machine learning flips this. Instead of writing the rules, you provide many examples (data) and let an algorithm discover the patterns. Show it thousands of labeled photos of cats and dogs, and it learns to tell them apart — without anyone writing "a cat has pointy ears."

This matters because some problems are nearly impossible to write rules for. Nobody can enumerate every rule that distinguishes spam from real email, or a fraudulent charge from a legitimate one. Learning from examples handles that fuzziness far better than hand-coded logic.

Deep learning: learning the features too

Classic machine learning often needs humans to decide which aspects of the data matter (the "features") — for example, telling the system to look at email sender, subject length, and certain keywords. Deep learning uses neural networks with many stacked layers that learn useful features automatically from raw data. That's why it excels at images, audio, and language, where hand-picking features is impractical.

A neural network is loosely inspired by neurons: simple units connected in layers, each passing signals forward. "Deep" just means "many layers." More layers can capture more complex patterns — at the cost of needing more data and computing power.

Training vs. inference

This distinction comes up constantly, so it's worth nailing down:

  • Training is the learning phase. The system processes large amounts of data and gradually adjusts its internal numbers to get better at the task. Training is expensive, slow, and usually done once (or occasionally) up front.
  • Inference is using the finished model to answer a new request. It's comparatively cheap and fast — this is the part end users actually touch when they ask a chatbot a question.

IT analogy

Training is like building and indexing a database: heavy, done occasionally, resource-intensive. Inference is like running a query against it: quick and repeatable. You wouldn't rebuild the index for every query, and you don't retrain a model for every question.

So what is "a model"?

After training, all that learning is stored as a big set of numbers called parameters (also called weights). A "model" is essentially this collection of tuned numbers plus the structure that uses them. When people say a model has "7 billion parameters," they mean it has 7 billion of these learned numbers.

You can think of parameters as a vast set of configuration values that were dialed in automatically during training. They encode everything the model "knows." Crucially, the model doesn't store a tidy database of facts you can look up or edit — the knowledge is spread across all those numbers.

Why GPUs matter

Neural networks boil down to enormous amounts of the same kind of math — multiplying and adding big grids of numbers (matrices), over and over. GPUs (graphics processing units) were built to do many similar calculations in parallel for rendering graphics, and that same strength makes them dramatically faster than ordinary CPUs for this work.

This is why AI hardware, cloud GPU capacity, and energy use are now major IT and budget considerations. Specialized AI accelerators (TPUs, NPUs) extend the same idea. The takeaway: modern AI is as much about parallel compute as it is about clever algorithms.

Key takeaways

  • ML learns patterns from examples instead of relying on hand-written rules.
  • Deep learning uses many-layered neural networks that learn features automatically.
  • Training (learning) is expensive and occasional; inference (answering) is cheap and frequent.
  • A model is a large set of learned parameters (weights); GPUs make training and inference practical.

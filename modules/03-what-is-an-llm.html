Module 03

What is an LLM?

⏱ ~13 min read

What you'll learn

  • The one core trick behind LLMs: next-token prediction.
  • What "parameters" and "model size" actually tell you.
  • Why an LLM can sound fluent and authoritative yet be wrong.

One simple idea, scaled up enormously

A Large Language Model (LLM) is a deep-learning model trained on a huge amount of text. Underneath the impressive results, it does one deceptively simple thing: predict the next token (the next word or word-fragment) given everything written so far.

Give it "The capital of France is" and it predicts "Paris" is a very likely next token. It appends that, then predicts the next token, and the next — one chunk at a time — until it has produced a full answer. That's it. The magic is that doing this extremely well, at massive scale, produces text that looks like reasoning, summarizing, translating, and coding.

IT analogy

It's autocomplete on an industrial scale. Your phone suggests the next word from a tiny model; an LLM does the same thing with a vastly larger model trained on far more text, so its suggestions can stretch into coherent paragraphs and code.

What "next-token prediction" really implies

Because the model is choosing likely next text, a few important consequences follow:

  • It's optimizing for plausible continuations, not verified true ones. Fluent and correct are different goals.
  • It has no built-in fact-checker or live database. Its "knowledge" is patterns baked into its parameters during training.
  • It generates text it has never seen verbatim — it's recombining patterns, not copying answers from a lookup table.

Parameters and model size

As covered in Module 2, the model's learning is stored in parameters (weights). "Model size" usually refers to how many parameters it has — millions, billions, sometimes more. Roughly speaking, more parameters means more capacity to capture patterns.

But bigger is not automatically better. A smaller model trained on better data, and tuned well for a task, can beat a larger one. Parameter count is one signal among several — alongside the training data, the tuning, and how well the model fits your actual job. Don't treat "more parameters" as a quality guarantee.

Why fluent can still be wrong

This is the single most important thing for IT staff to internalize. An LLM produces grammatical, confident, well-structured prose regardless of whether the content is accurate. The smooth tone is a product of predicting natural-sounding text, not a sign of correctness.

So an LLM can invent a citation, a configuration flag, or an API endpoint that sounds completely real but doesn't exist. We'll dig into this in Module 10 (Limitations & Risks). For now, adopt the working rule: treat LLM output as a knowledgeable-sounding draft that must be verified before you rely on it for anything that matters.

Why answers can vary

Ask the same question twice and you may get two different answers. LLMs usually pick the next token by sampling from a range of likely options rather than always taking the single most likely one. That built-in randomness is useful for creativity but makes exact repeatability tricky — more on this in Module 6.

Key takeaways

  • An LLM repeatedly predicts the next token; that simple loop produces fluent text.
  • It optimizes for plausible wording, not verified truth.
  • Parameter count hints at capacity but isn't a guarantee of quality.
  • Fluent and confident ≠ correct — always verify what matters.
